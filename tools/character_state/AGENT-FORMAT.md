# Agent query contract — v2

`agents.json` is an indexed projection of `state.json`, generated by the same extraction. The detailed state remains available. Identification:

```json
{"format": "melvor2-character-agents", "schema_version": 2}
```

Breaking changes require a new `schema_version`; consumers must reject unknown versions. Version 2 replaces the Portuguese keys and identifiers from v1 with English. Regenerate snapshots instead of reusing a v1 cache. Skill, component, type, and stat IDs are the official English game IDs. Queries match case insensitively without guessing aliases or confusing stats from different components.

## Recommended queries

```powershell
.\query-character.ps1 -Skill Smithing -Stat SkipStepChance
.\query-character.ps1 -Skill Smithing
.\query-character.ps1 -Skill Smithing -Stat SkipStepChance -Component Action -Type ArtisanAction
```

Direct equivalent, including subprocess calls:

```powershell
.\.venv\Scripts\python.exe -X utf8 -I tools\character_state\query.py --skill Smithing --stat SkipStepChance
```

By default, the query rereads the save, regenerates snapshots, and returns UTF-8 JSON. Extraction messages go to stderr. Exit code `0` means the query ran, but the agent must still inspect `status`: `found` or `unidentified`. A nonzero exit code indicates an error. There is no automatic fallback to an old file. Invalid arguments may be reported by argparse/PowerShell on stderr.

With `-Cache` / `--cache`, the query reads only `agents.json`; it neither rereads the game nor verifies that the save is unchanged. The response marks `read_mode: cache`. A recent extraction can still describe an old save: check **both timestamps**, save age, and character identity. `-Save`, `-Exe`, and `-Output` correspond to extraction arguments; `-Save`/`-Exe` cannot be combined with `-Cache`.

## Indexed structure

A stat's path is:

```text
skills.Smithing.modifiers.Action.ArtisanAction.SkipStepChance
```

Example node (illustrative values):

```json
{
  "unit": "percentage_fraction",
  "confirmed_general": {
    "value": 0.06,
    "percentage": 6,
    "contributions": [
      {"source": "s_example_gloves", "value": 0.01},
      {"source": "s_example_anvil", "value": 0.05}
    ]
  },
  "contextual": [],
  "uncertain": [],
  "final_value": null,
  "complete": false
}
```

`sources` resolves references in one table with `type`, `id`, `name`, and `via`. Actual keys are deterministic hashes of source type, ID, and acquisition path, not positional numbers. Contextual/uncertain contributions preserve `context`, `condition`, `scaling`, `from_context`, and `note` when present. A scaled contribution contains the recorded coefficient, not the result of an unevaluated scale.

Each skill also contains `level` and `xp`. The document includes `total_level`, `activity`, `snapshot`, `coverage`, and `other_and_global_bonuses`. The snapshot identifies character/UUID, mode, save version, save/game package SHA-256, and save/extraction timestamps in ISO 8601 with time zones.

## Query response

Responses use `format: melvor2-character-agents-query`, version `2`, with `status`, `read_mode`, `snapshot`, `skill`, `level`, `xp`, `coverage`, `modifier`, and only the referenced `sources`. Without `--stat`, the response contains `modifiers` for the whole skill. `snapshot.save_age_seconds` is calculated at query time.

`other_and_global_bonuses` includes other-component candidates for the same stat and **all global groups**, because group names may differ from stat names. A candidate's presence does not confirm that it applies to the queried skill. Global groups are not expanded.

## Numeric rules

- `percentage_fraction`: display `value * 100`; `0.06` represents `6%`. `percentage` is only a unit conversion, not another contribution.
- `ms`: milliseconds, preserving the sign.
- `game_value`: the unit was not inferred; preserve the raw value and check the description/mechanics before using it in calculations.
- `confirmed_general` sums only general modifiers confirmed by covered sources. The entries in `contributions` **are already included**.
- `final_value: null` and `complete: false` distinguish the subtotal from the final game value. Base values, limits, multipliers, and uninterpreted sources are not modeled by this interface.
- Contextual, uncertain, and global bonuses are excluded from the subtotal. Do not apply them without verifying context, conditions, scaling, and combination rules.
- An absent stat returns `status: unidentified` and `modifier: null`. A stat with only contextual/uncertain contributions has `confirmed_general: null`. **Neither case means zero.** An explicit `value: 0` is a known subtotal.
- Multiple matches cause an error; select component and type. Unknown skills and incompatible versions also cause errors.

Coverage remains partial and is declared in every response. This contract organizes available knowledge; it does not expand the sources interpreted by the reader. Use `state.json`, `bonus.json`, and `decoded_state.json` for a detailed audit.
